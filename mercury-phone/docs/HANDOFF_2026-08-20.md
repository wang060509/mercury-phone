## 架构决定

本轮追加确认：Web/PWA 是 Mercury 的主要交付形态。普通用户通过 HTTPS 链接打开并可安装到手机主屏，不需要 Node；业务数据继续保存在浏览器本地，模型连接由用户自带。生产模型请求通过同源 Stateless Relay，relay 不长期保存 Key、聊天或资源。原生/Android 包只保留为以后可能的薄包装，不是当前并行产品；账户、云数据库和同步不随上线进入范围。

该决定来自对静态本地优先、带服务端路由的 Web/PWA 与跨端实现的对照。吸收的是安装入口、缓存/更新、同源 API、版本化本地数据和失败恢复；不复制参考代码、命名、UI、资产、文案或私有字段，也不为工程观感迁移框架。当前 `dist/` 还没有 manifest、Service Worker、生产托管或 Stateless Relay，因此“方向已确认”不等于“已经上线”。

Connection Readiness 属于现有 Chat Generation Workflow，不属于 controller，也不是第二条发送路径。Chat controller 仍只负责 Adapter、用户意图和呈现；它不能读取或复制 session credential。

当前标签页 session Key 的隔离是预期隐私边界：关闭标签页后 Key 消失，新标签页必须重新建立连接。不得为了跨标签页便利把 Key 暗中写入长期 storage。只有用户主动开启“记住 API Key”才允许长期保存。

Conversation Transfer 分配新 timeline 时必须同时检查 Chat 私有正文和 shared session：只有场景/设置、尚未保存消息的 timeline 也是有效会话，不得被导入覆盖。导入后，Chat 必须把缺失世界书、缺失 Profile/default fallback 和角色重绑定显示在目标会话回执中；安全降级不能只存在于 workflow 返回值里。

纵向聊天闭环使用 Mercury 自有 fixtures 验证，避免正式测试依赖最终必须删除的 `reference-sources/`。真实来源文件只用于隔离浏览器 QA。

App 加载只吸收成熟项目的关键/延迟分层、资源分组、CSS-before-script、Promise 去重和 retry reset；明确拒绝吞掉样式错误、加载失败后仍运行 App，以及页面启动后立刻预取全部非关键资源。没有复制任何参考代码、命名、UI、资产、文案或私有字段。

## Reference Before Reinvention 结论

本次实现前只审计了允许参考项目的行为分层，没有复制代码、命名、UI、资产、文案或私有字段：

- 成熟参考实现：连接字段完整性在用户消息持久化之前判断。
- Wanwan：配置错误与普通请求错误分开呈现，并提供直接恢复动作。
- Wangwang：错误使用持久页内卡片和明确 retry，而不是只依赖瞬时 toast。
- Xiaolongbao 公开子集没有提供足够完整的 Chat 错误恢复实现，因此没有强行套用其结构。

Mercury 最终保留了自己的 Workflow、Adapter、ConversationV2、视觉和交互语言。

### 追加：API 连接复杂度审计

对照成熟小手机、Web/PWA 与聊天工具后，Mercury 不是“API 太简单所以不能用”，而是“Provider 广度窄、Chat 主链深度已经合格”。参考面板更复杂，主要因为它们已经增加主/备用线路、记忆/工具/游戏/图片/语音 API、原生协议、流式、工具循环和调试记录；这些不是基础聊天可用性的同义词。Mercury 已有同一 AITransport/Provider Adapter、当前标签页 Key、真实 Test Message、可选 `/models`、endpoint 归一化、超时/取消、错误分类/脱敏与 Chat 失败恢复，不能为看起来成熟而复制多 Provider UI。

API 审计最初发现三个明确 P1，其中 API-01 已完成：

1. **已解决（API-01）**：Cinema workflow 只调用 `generateCinema(request, { signal })`；credential resolution、relay endpoint/payload、默认超时和响应验证留在 AITransport Implementation，`readCredential/postLocal` 已私有化。四条高层操作均覆盖调用前已取消返回 `AbortError` 且 0 fetch。
2. **待处理（API-02）**：Provider URL 只检查字面 hostname；生产 Stateless Relay 需要 A/AAAA、IPv4/IPv6、DNS rebinding/连接绑定与重定向安全合同。OWASP 明确指出只查 hostname、只信首次 DNS、忽略特殊地址都不足以防 SSRF。
3. **待处理（API-02/API-03）**：上游响应先完整 `text()` 再检查 512 KiB，不能在下载中阻止超大响应；生产 Adapter 还需要 rate/concurrency/origin/host、无正文/Key 日志和 debug 禁用边界。

当前顺序：API-02 Provider Network Policy → API-03 生产 Stateless Relay Adapter → PWA-01 安装/更新。模型列表 + 手动模型回退、少量命名连接只在主链稳定后评估；原生 Anthropic/Gemini、自动主备、流式、按功能 API 与 Model Parameters 不在当前范围。

角色导入 P1 另行审计了四套允许参考的成熟路径。接受的共同原则是：导入提交返回可读结果并刷新列表；新角色进入显眼位置；首条与备选分开保留；导入结果显式区分新增/跳过/错误。Mercury 拒绝了参考中的瞬时 toast、同 ID 覆盖和“缺少开场就自动编造问候”，没有复制其代码、命名、字段、UI、资产或文案。完整结论已写入 `docs/reference-architecture-review.md`。
